# MCP 接入设计

第一版 stdio 接入已实现：后台连接、工具发现与组装、主模型调用及退出清理。远程 HTTP 等后续能力尚未实现。

## 大概思路

使用官方 MCP Python SDK，由 MiniAgent 自己连接 MCP Server。第一版只支持 stdio，通过 `.mcp.json` 配置服务器名称、`command`、`args` 和可选 `env`；Windows 下命令与参数分开传入，不拼接成 PowerShell 命令。没有配置文件时只使用内置工具。

启动 `python core.py` 后立即创建后台初始化任务，连接配置中的服务器、获取工具列表并转换为现有的 function 工具定义。连接期间正常展示会话、等待用户输入，也允许辅助 LLM 进行记忆召回。

```text
启动 main
  ├─ 后台任务：读取配置 → 连接 MCP → 获取工具 → 组装完整工具列表和调用路由
  └─ 展示会话 → 等待用户输入 → 辅助 LLM 召回记忆
                                  ↓
                          await MCP 初始化任务
                                  ↓
                         携带完整工具列表请求主 LLM
```

- 首次主 LLM 请求前必须等待初始化任务；已经完成时直接取得结果。辅助 LLM 不依赖工具列表，不必等待。
- 初始化任务只创建一次，完成后统一交付工具定义和路由，避免读取到组装一半的列表。后续问题和会话切换复用连接及工具列表，运行期间不刷新。
- 对模型暴露带服务器前缀的 MCP 工具名，检查名称合法性和冲突，内部映射到连接及原始工具名。内置工具继续调用本地函数，MCP 工具通过客户端调用；均经过现有工具 Hook 流程。
- MCP 文本和结构化结果转换为字符串，继续使用原有 `function_call_output`，保留调用的 `call_id`；暂不接入图片等多模态结果。
- 单个服务器连接失败或超时，提示原因并跳过，保留内置工具和其他成功连接的工具。调用失败返回错误结果，不自动重试工具调用。
- 退出时收尾初始化任务，关闭已建立的 MCP 连接；即使用户尚未提问就退出，也要完成清理。

第一版暂不加入远程 HTTP、自动重连、动态工具刷新，以及 MCP Resources、Prompts 等能力。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `mcp_client.py`，新增 | 读取配置、管理连接和生命周期、发现并转换工具、维护名称映射、执行 MCP 调用。 |
| `.mcp.json`，新增 | 保存需要连接的服务器及 stdio 启动配置。 |
| `tools.py`，修改 | `initialize_tools` 等待 MCP 发现完成，再调用 `assemble_tools` 组合本地工具和 MCP 工具，返回完整工具列表。 |
| `core.py`，修改 | 启动后台初始化；主 LLM 请求前等待并取得完整工具列表；分发 MCP 调用；退出时清理连接。 |
| `pyproject.toml`，修改 | 增加 MCP Python SDK 依赖，锁定与安装仍由用户执行。 |
| `README.md`，修改 | 实际新增文件后更新项目结构，并补充最简配置说明。 |
| `tests/live_mcp.py`，新增 | 生成临时真实 stdio 服务，通过实际 Agent 循环验证主模型的一次 MCP 工具调用，并清理进程和临时文件。 |

`tools.py` 保留内置工具定义与处理函数，由 `assemble_tools` 组合工具列表，不直接修改其全局列表。MCP 连接、发现和调用仍由 `mcp_client.py` 负责。现有 Hook 和会话消息格式继续沿用；MCP 设计进展集中更新本文。

依赖在 `pyproject.toml` 声明为 `mcp>=1.26.0,<2`，以保留项目的 Python 3.10 支持；安装由用户执行。

## 实现约定与验证

- 配置结构为 `{"mcpServers": {"服务器名称": {"command": "可执行文件", "args": [], "env": {}}}}`，默认配置为空。`env` 不进行环境变量占位符展开，SDK 仅继承默认允许的环境变量及显式配置。
- 服务器名使用英文字母、数字、下划线或短横线；暴露工具名为 `mcp__服务器名__原工具名`，须符合 function 名称字符限制且不超过 64 字符。非法或重名工具所在服务器的工具不发布。
- 每个服务器有独立后台任务，在同一个任务内进入和退出 SDK 连接上下文；初始化任务等待各服务器发现完成，再调用 `assemble_tools`。工具发现支持分页，初始化和发现限时 30 秒（子进程启动后开始计时），单次 MCP 请求限时 60 秒，不自动重连或重试工具调用。
- 主模型在辅助召回之后直接 `await` 初始化结果。正常结束或 Ctrl+C 时，主入口只调用 `await mcp.close(tools_ready)`；由该方法统一取消初始化及连接任务，再等待各任务退出 SDK 上下文并回收子进程，不使用 `shield` 或额外停止信号。
- 输出字符串为 JSON，保留 `content`、`structuredContent` 和 `isError`；调用异常返回错误，非文本内容仅返回暂不支持的说明。MCP 工具经过现有 Hook，但不增加新的审批规则；当前权限 Hook 默认未启用。

在 Windows PowerShell 中执行：

```powershell
.venv\Scripts\python.exe -B -X utf8 tests/live_mcp.py
```

测试在 `tests/` 下创建独立临时目录，内含服务源码、配置、随机口令、执行次数和会话 JSONL。临时服务只暴露读取口令的工具；首次主模型请求指定该工具，第二次禁止工具并要求回答，最多两次 API 请求。复用实际 Agent 循环、工具组装、路由和持久化，禁用终端渲染、辅助记忆调用和压缩，验证仅一次服务执行、工具结果配对及最终口令。

通过 `finally` 关闭连接、检查服务进程已退出，再由临时目录上下文删除文件；服务未正常退出时仅终止本次持有句柄的测试进程，并报错。测试脚本保留，临时生成的程序和文件不保留。

2026-11-10 真实验证通过：2 次主模型请求、1 次 MCP 工具调用，最终回答正确，服务进程和临时文件已清理。测试进程无 Windows 控制台，故跳过 UI 渲染，未验证终端显示。

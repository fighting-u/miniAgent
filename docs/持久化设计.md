## 1. 文件组织

每个会话使用一个只追加的 JSONL 文件，一行保存一条记录：

```text
sessions/YYYY/MM/DD/<session-id>.jsonl
```

- 路径相对于项目根目录，日期使用会话创建时的本地日期（Asia/Shanghai）。
- `session-id` 使用带时间信息的 UUIDv7，便于按创建时间排序；同毫秒内不要求严格单调。
- 会话跨天仍写入原文件，恢复同一会话时继续追加。

## 2. 最外层结构

| 字段 | 含义 |
| --- | --- |
| `timestamp` | 写入时间，使用带时区、毫秒精度的 ISO 8601 字符串。 |
| `ordinal` | 文件内序号，从 0 开始，每条记录递增 1。 |
| `type` | `messages` 时表示上下文内容；`compact` 表示一次上下文压缩记录。 |
| `payload` | 具体内容，结构随外层 `type` 变化。 |
| `turn_id` | 对应每次用户请求的序号，从 0 开始；同一用户请求中的工具循环、压缩等都对应同一个turn。 |

`compact` 的关联规则与 payload 后续设计，具体涉及到转存，提取摘要等。

## 3. messages 内容与示例

`messages` 虽为复数，每行仍只保存一个 item。当前模型与工具交互包含四种 `payload.type`：

| 类型 | 来源 |
| --- | --- |
| `message` | 消息请求和响应，包括user，developer，assistant等 |
| `reasoning` | llm的推理摘要等内容，不放在message里是因为openai的api格式里区分开了为2类type |
| `function_call` | 模型返回的 `function_call`。 |
| `function_call_output` | Harness 生成的 `function_call_output`。 |

`payload` 保留原始 API item 字段，并增加 `metadata` 保存补充信息：

| `payload.metadata` 字段 | 含义 |
| --- | --- |
| `api_format` | LLM API 的协议格式，当前使用 `openai_responses`，不表示供应商或模型名称。 |
| `model_name` | 请求使用的模型名称，仅模型返回的 `message`、`reasoning` 记录携带；其他记录省略。 |

`metadata` 是持久化层附加的信息，恢复 API 输入时需移除。

以下示例展开排版方便阅读，实际 JSONL 每条只占一行。文本中的“……”仅用于展示，落盘保存完整内容。四条记录属于同一 turn：第一次响应调用工具，第二次响应给出回答。

### reasoning

```json
{
  "timestamp": "2026-11-09T14:23:45.456+08:00",
  "ordinal": 0,
  "type": "messages",
  "payload": {
    "type": "reasoning",
    "metadata": {
      "api_format": "openai_responses",
      "model_name": "qwen3.7-flash"
    },
    "id": "msg_reasoning_001",
    "summary": [
      {
        "type": "summary_text",
        "text": "先读取 README.md。"
      }
    ]
  },
  "turn_id": 0
}
```

### function_call

```json
{
  "timestamp": "2026-11-09T14:23:45.458+08:00",
  "ordinal": 1,
  "type": "messages",
  "payload": {
    "type": "function_call",
    "metadata": {
      "api_format": "openai_responses"
    },
    "id": "msg_call_001",
    "call_id": "call_001",
    "name": "read_file",
    "arguments": "{\"path\":\"README.md\"}",
    "status": "completed"
  },
  "turn_id": 0
}
```

### function_call_output

```json
{
  "timestamp": "2026-11-09T14:23:45.517+08:00",
  "ordinal": 2,
  "type": "messages",
  "payload": {
    "type": "function_call_output",
    "metadata": {
      "api_format": "openai_responses"
    },
    "call_id": "call_001",
    "output": "# MiniAgent\n这是一个学习项目……"
  },
  "turn_id": 0
}
```

工具输出由 Harness 生成，`call_id` 必须与对应调用原样配对，不额外补造 `id` 或 `status`。

## 4. 序列化与恢复规则

- 按 `response.output` 原始顺序逐项写入，每个工具调用各占一行；执行工具后分别追加结果。
- SDK 对象转为 JSON 字典时使用字段别名，并递归省略对象中值为 `None` 的字段；保留空列表、空对象、空字符串、0 和 false，不删除列表元素。
- `arguments` 保留原始 JSON 字符串，不解析或改写其内部内容；当前 `output` 保持字符串。
- 保留 API 原始类型名，不做类型映射；恢复 API 输入时移除持久化层附加的 `metadata`。
- 省略可选的 null 字段旨在恢复可用上下文，不保证逐字段还原原始响应；无需统一补回 null，具体输入兼容性在实现时确认。
- 使用 UTF-8，中文不转义；每条先完成序列化，再追加内容及换行。未知 item 类型不得静默丢弃。
- 恢复时按文件顺序读取并校验 `ordinal`，继续追加时沿用会话标识与已有序号。

## 5. 已实现的写入与恢复

- `session_store.py` 负责存储，`core.py` 在用户输入、模型响应、各个工具结果生成后立即追加；Hook 续跑和计划提醒也保存在同一个 turn 内。
- 主循环必须传入 `SessionStore`，所有会话内容都持久化，不提供无 session 的运行模式。
- `/delete` 在选择与二次确认后仅删除指定会话 JSONL；删除当前会话时创建新文件并清空当前内存历史，不影响其他会话文件。
- 用户输入保存为 `payload.type=message`、`role=user`、`content=原始文本`，metadata 仅含 `api_format`，不记录模型名称。
- Harness 注入的计划提醒与 Stop Hook 续跑要求使用 `role=system`，沿用当前 turn_id，不作为新的用户输入。
- 每条记录写完后刷新并同步到磁盘；无需等到正常退出才保存。
- `python core.py` 自动加载最近写入的会话；`/resume` 选择其他会话，`/new` 创建新会话，`/q` 退出。加载时校验历史，移除 metadata 后恢复上下文，并接续原文件的 ordinal、turn_id。
- 会话发现仅扫描日期目录下的 JSONL，按文件修改时间倒序排列；列表预览只读取首条用户问题并截短到 40 个字符，不把全部会话加载进上下文。
- 工具调用已保存而结果缺失时，加载本身不修改文件；开始交互前追加“中断后结果未确认”的工具输出，不自动重跑工具。
- 损坏行、末行缺换行、序号不连续、不支持的协议或 compact 记录明确报错，不自动截断或改写文件。

当前只支持单进程、未压缩会话的恢复；压缩后的实际上下文尚不能靠消息日志完整重建。`compact.payload` 与大工具结果外置策略后续设计。

## 6. 持久化专项测试

在项目根目录执行（PowerShell）：

```powershell
# 本地测试：真实 SDK 配合模拟 HTTP 响应，不调用远程模型。
.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_sessions.py -v

# 真实 API 测试：使用现有 MODEL、BASE_URL、DASHSCOPE_API_KEY 配置。
.venv\Scripts\python.exe -X utf8 tests/live_sessions.py
```

- 本地测试覆盖 JSONL 字段、UUIDv7、None 省略、SDK 别名、读取与 glob 工具、call_id 配对、CLI 加载续聊、工具执行中断及损坏记录拒绝加载。
- 真实测试用两个独立进程：第一进程调用 read_file 读取随机口令并在回复后硬退出；第二进程重新加载 JSONL，禁用工具，仅凭历史回答口令。同时检查原文件前缀未被覆盖，ordinal 连续、turn_id 递增。
- 测试禁用辅助记忆调用，使用短对话、小工具结果，并在发生压缩归档或摘要时立即失败。本地测试与真实测试均使用独立临时目录；真实测试由父进程统一管理，子进程硬退出或测试失败后，仍在父进程退出测试上下文时自动清理本次 JSONL、工具读取文件和状态文件，不写入正式 sessions。已有会话文件不清理。

2026-11-09 持久化初版验证结果：本地 7 项测试全部通过；使用当前配置的 qwen3.7-flash 完成真实跨进程续聊，3 次 API 请求保存 9 条记录，未触发压缩。后续终端交互改动未复跑测试，由用户手动验证，参见 [终端运行界面设计](终端运行界面设计.md)。

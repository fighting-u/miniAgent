# 终端运行界面设计

## 启动与命令

执行 `python core.py`，自动恢复最近写入的会话，显示历史后等待输入；没有记录时创建新会话。最近会话按 JSONL 文件修改时间判断，不按创建日期判断。

| 输入 | 行为 |
| --- | --- |
| 普通文字 | 开始新的用户请求，持久化后调用 Agent。 |
| `/new` | 新建会话并切换，保留原文件。 |
| `/resume` | 打开会话选择菜单，确认后加载并显示历史。 |
| `/q` | 退出；下次启动自动恢复最近写入的会话。 |
| 空输入 | 在当前输入框等待，不提交、不新建提示行。 |

斜杠命令不写入聊天记录，不增加 turn_id，不触发模型调用。未知斜杠命令显示可用命令。

## 输入与会话选择

- 使用 `prompt-toolkit` 的普通终端输入模式，保留终端滚动历史。
- 输入为空时显示“输入问题，或输入 / 查看命令”，开始输入后占位文字消失。
- 主输入框在按键层拦截空白回车，避免空 prompt 被提交后留下重复占位行；会话选择菜单仍可正常取消。
- 输入 `/` 后显示命令和中文说明；上下键选择、Tab 补全、Enter 确认并提交。
- 底部显示模型、工作目录和常用命令。
- 诊断日志仅写入 `logs/` 文件，不输出到终端；聊天内容和必要的操作提示照常展示。
- `/resume` 菜单按最近时间倒序排列，展示选择序号、最近时间、首条用户问题；问题合并为单行，最多 40 字符，超出显示省略号，不显示会话 ID。
- 选择菜单支持方向键、Tab、Enter，也可输入序号；Ctrl+C 取消切换，保留当前会话。

## 历史展示与切换

- 启动恢复或切换会话时清理当前屏幕，按原始顺序重新展示内容；仅做本地渲染，不重新调用模型或工具。
- `/resume` 确认并成功加载后，先刷新已有输出，再在 Windows 使用原生 `cls` 清屏，然后展示选中会话；取消或加载失败不清屏。清屏不删除 JSONL 文件。
- 带样式的标题和角色标签使用 `FormattedText` 显式包装，避免把样式元组列表原样打印出来。
- 用户与助手消息按角色标记并显示正文；推理摘要、工具名称和参数、工具结果分别标记，细节最多展示 600 字符。
- 截断仅影响展示，模型上下文和 JSONL 内容保持完整。新回答使用相同的消息展示方式。
- 当前对话也使用同一渲染函数：每次 API 响应返回后按顺序展示推理、工具调用及助手消息；每个工具结果产生并落盘后立即展示，权限拒绝、参数错误及内部续跑提示同样显示。最终回答不重复打印。
- 当前仍为非流式 API 请求，展示发生在响应返回后，不是逐 Token 输出。
- 切换时清空上一会话的运行时计划；工具调用有缺失结果时仍按持久化模块的中断规则处理。
- 加载失败时显示原因并保留原文件；手动切换失败则继续当前会话，启动恢复失败则明确提示并创建新会话。
- 输入处 Ctrl+C 或 EOF 退出；模型或工具执行中 Ctrl+C 结束本次程序，已落盘内容保留。

## 文件边界与验证

`terminal_ui.py` 负责输入、菜单和渲染；`session_store.py` 负责文件发现与持久化；`core.py` 负责命令分发、会话切换和模型循环。

本次按要求未运行测试。手动检查：启动恢复历史 → 输入 `/` 查看菜单 → `/new` 聊天 → `/resume` 选择旧会话并继续提问 → `/q` 退出后再次启动。另检查占位文字、中文显示、菜单取消和长问题截断。菜单和命令逻辑可以自动化测试，但终端排版及按键手感仍需实机确认。

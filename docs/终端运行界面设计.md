# 终端运行界面设计

## 启动与命令

先执行 `python -m src` 启动常驻程序，再在另一个终端执行 `python -m src.terminal` 连接。常驻端恢复最近写入的会话，客户端取得历史快照后等待输入；没有记录时在常驻端内存中准备新会话，首次实际用户输入时才创建文件。最近会话按 JSONL 文件修改时间判断，不按创建日期判断。

| 输入 | 行为 |
| --- | --- |
| 普通文字 | 开始新的用户请求，持久化后调用 Agent。 |
| `/new` | 常驻端准备新会话，客户端切换标识并清屏；首次实际用户输入时才创建文件，保留原会话和文件。 |
| `/resume` | 打开会话选择菜单，确认后加载并显示历史。 |
| `/delete` | 从同样的会话列表选择，二次确认后删除该会话文件；若是当前会话，清屏并开启新会话。 |
| `/q` | 断开当前终端；常驻程序和已接受的任务继续运行，再次连接可恢复历史。 |
| 空输入 | 在当前输入框等待，不提交、不新建提示行。 |

斜杠命令不写入聊天记录，不增加 turn_id，不触发模型调用。未知斜杠命令显示可用命令。

## 输入与会话选择

- 使用 `prompt-toolkit` 的普通终端输入模式，保留终端滚动历史。
- 主输入、会话选择和删除确认均使用异步方法 `await PromptSession.prompt_async()`，等待按键时让出事件循环，使本地网络等异步任务继续执行；长期记忆提取在常驻程序的事件循环中运行；通过 `patch_stdout()` 避免后台输出破坏输入框。
- 输入为空时显示“输入问题，或输入 / 查看命令”，开始输入后占位文字消失。
- 主输入框在按键层拦截空白回车，避免空 prompt 被提交后留下重复占位行；会话选择菜单仍可正常取消。
- 输入 `/` 后显示命令和中文说明；上下键选择、Tab 补全、Enter 确认并提交。
- 底部显示模型、工作目录和常用命令。
- 诊断日志仅写入 `logs/` 文件，不输出到终端；聊天内容和必要的操作提示照常展示。
- 会话列表由常驻端发送，客户端仅保存会话标识，不直接扫描或修改文件。
- `/resume` 菜单按最近时间倒序排列，展示选择序号、最近时间、首条用户问题；问题合并为单行，最多 40 字符，超出显示省略号，不显示会话 ID。
- 选择菜单支持方向键、Tab、Enter，也可输入序号；Ctrl+C 取消切换，保留当前会话。
- `/delete` 复用会话列表，选中后再次显示最近时间与问题；仅输入 `y` 或 `yes` 才删除，回车或 Ctrl+C 取消。只删除选中的 JSONL，不清空目录，删除后无法通过程序恢复；删除其他会话不切换当前对话。

## 历史展示与切换

- 启动恢复或切换会话时清理当前屏幕，按原始顺序重新展示内容；仅做本地渲染，不重新调用模型或工具。
- `/resume` 确认并成功加载后，先刷新已有输出，再在 Windows 使用原生 `cls` 清屏，然后展示选中会话；取消或加载失败不清屏。清屏不删除 JSONL 文件。
- 带样式的标题和角色标签使用 `FormattedText` 显式包装，避免把样式元组列表原样打印出来。
- 用户与助手消息按角色标记并显示正文；推理摘要、工具名称和参数、工具结果分别标记，细节最多展示 600 字符。
- system 消息在历史和实时输出中均以独立颜色、加粗的“系统”标题展示；Harness 注入的计划提醒和 Stop Hook 续跑提示使用该样式。
- 截断仅影响展示，模型上下文和 JSONL 内容保持完整。新回答使用相同的消息展示方式。
- 当前对话也使用同一渲染函数：每次 API 响应返回后按顺序展示推理、工具调用及助手消息；每个工具结果产生并落盘后立即展示，权限拒绝、参数错误及内部续跑提示同样显示。最终回答不重复打印。
- 当前仍为非流式 API 请求，展示发生在响应返回后，不是逐 Token 输出。
- 运行时计划由常驻端按会话分别持有；重建会话运行状态时从空计划开始。工具调用有缺失结果时仍按持久化模块的中断规则处理。
- 加载失败时显示原因并保留原文件；手动切换失败则继续当前会话，启动恢复失败则明确提示并创建新会话。
- 客户端 Ctrl+C、EOF 或 /q 只断开连接；常驻端继续已接受的请求并保存结果。常驻程序在自己的终端收到 Ctrl+C 时关闭入口并完成资源收尾。
- 权限审批由客户端展示并回传 /approve 控制命令，答复绕过普通输入队列；断线或超时拒绝。

## 文件边界与验证

`src/ui/terminal_ui.py` 负责输入、菜单和渲染；`src/terminal.py` 负责客户端连接、命令交互及事件接收。`src/channels/terminal.py` 是常驻端监听器，统一绑定回复目标。`src/runtime/runtime.py` 负责队列消费、会话命令和事件持久化，`src/session/session_store.py` 仅负责文件发现、写入与恢复。

原 activate_session 已拆除：中断恢复与历史快照由 Runtime 处理，清屏渲染仍由 TerminalUI 负责。客户端断线不改变模型历史，其他入口选择同一会话时可以取得已保存的内容；当前不向所有连接实时广播。

2026-11-14 验证：本地回归 13 项通过；独立常驻端和终端客户端的真实测试完成 /new、read_file、PowerShell、断开重连、实际 /resume 菜单和历史续聊。输入框和菜单通过 prompt-toolkit 管道输入投喂真实按键，终端外观和手工操作手感仍需实机确认。测试脚本为 tests/integration/live_channels.py，成功或失败均关闭本次子进程并清理临时目录。

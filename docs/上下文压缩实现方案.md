# miniAgent 上下文压缩实现方案

状态为待验收设计。以下路径和伪代码以 miniAgent 当前仓库代码为基线。本文的「历史」指 `session.messages`，即下一次主模型请求可用的 Responses items。「原历史」指本次压缩开始时的有效历史，可能已经包含上一次的压缩结果。

## 1. 整体设计

采用 Codex 本地摘要的思路。主模型负责读历史、写续接摘要；Harness 负责决定何时压缩、哪些用户原话值得占用保留预算，以及何时把新历史写回会话。全局仅在 `AgentRuntime` 创建**一个** `ContextCompactor` 实例，手动 `/compact` 和两处自动检测共享该实例；工具注册表里不提供 `compact` 工具。

```text
                            ┌─ 工作副本 + 中文摘要请求 ── Responses API ── 摘要文本 ─┐
手动命令 / 自动达到阈值 ── 原历史 ┤                                                 ├─ 新历史
                            └─ 从新往旧选取真实用户文本，再恢复时间顺序 ────────────┘
新历史 = 保留的用户消息 + 一条带 SUMMARY_PREFIX 的 user 消息
提交   = 向现有 JSONL 追加一条 compacted，写入成功后原地替换 session.messages
```

例如，旧历史是 `[用户 A, 摘要 S1, 用户 B, 模型工具调用, 工具结果]`。第二次压缩时，模型能读到 `S1` 和工具结果。预算足够时，Harness 重建出 `[用户 A, 用户 B, 摘要 S2]`。如果这次是新轮开始前触发，当前刚收到的 `用户 C` 随后才加入，第一次普通请求看到的是 `[用户 A, 用户 B, 摘要 S2, 用户 C]`。

当前仓库已删除旧的 `src/context_compact/`。开发时将新增 `src/compact/` 和 `src/models/`，并清理 `TurnRunner.run_turn()` 中残留的响应式压缩分支以及 `src/system_prompt.py` 中旧的本地转存提示词。旧设计文档里的字符数管线、工具结果转存和模型主动压缩不作为本次实现的前置步骤。

## 2. 触发点与执行顺序

| 入口 | 检测所见的历史 | 行为 |
| --- | --- | --- |
| 新 turn 开始 | 上一轮结束时的有效历史，含中断恢复补齐的工具结果 | 在 `start_turn()` 写入新用户消息之前检查一次。非空且估算值 `>=` 自动阈值才压缩，期间向入口发送中文 `status` 提示。压缩成功后再开始新 turn |
| 本 turn 需要下一次普通模型请求 | 本次 `response.output`、整批本地/MCP 工具结果，以及批末 Hook 已写入的系统消息 | 在回到循环发下一次请求之前检查一次，期间向入口发送中文 `status` 提示。没有本地工具调用但 `Stop` Hook 追加消息要求续跑时，也在这一位置检查 |
| 当前入口发送 `/compact` | 指定会话当前的完整有效历史 | 跳过阈值比较，完成一次压缩后给入口发中文 `status`。命令本身不进历史，不递增 `turn_id`，也不启动后续普通模型请求 |

### 2.1 新 turn 开始前

现在 `MessageProcessor` 先调用 `SessionManager.start_turn()`，由后者一起补齐旧调用并落盘新用户消息，然后才交给 `TurnRunner`。建议把「补齐中断结果」从 `start_turn()` 拆出，并把轮前顺序集中到 `TurnRunner.run_turn()`。`MessageProcessor` 仍负责入口占用、全局信号量和 `PreUserPromptSubmit`。

```python
# 以下代码位于已取得会话占用的普通聊天路径。
sessions.recover_pending_tools(session)          # 使用原 turn_id，写盘并追加到内存
await compactor.maybe_compact(
    session,
    phase="pre_turn",
    instructions_provider=lambda: build_system_prompt(config, tool_context.cwd),
    tools=available_tools,
    on_status=send_status,
)
sessions.start_turn(session, inbound.input)      # 递增 turn_id，写入且只写入一次
sessions.bind(inbound.channel_id, session.id)
# 按现有方式召回记忆、构造本轮 instructions，然后进入普通模型循环。
```

`instructions_provider` 仅在没有有效主基准、必须走全量估算时才调用，避免常规对话每轮重复扫描技能与记忆目录。

轮前压缩记录归属**上一轮**。如果摘要请求失败，外层把错误发回入口，刚提交的文本还没有记成新 turn。第一个 turn 和 `/new` 后尚无历史的会话直接进入首次聊天。`SessionManager.reload()` 仅对已经创建文件的会话执行（`if not session.persisted: return`）。

### 2.2 本 turn 内

`TurnRunner` 的循环保留一个共同的续跑出口。`ToolManager.execute_batch()` 已保证结果按调用顺序落盘，最后才追加 `PostToolBatch` 消息。把检测放在它返回之后，可避免把一个并行批次拆在两个上下文窗口里。

```python
while True:
    response = await client.responses.create(
        model=model, instructions=instructions,
        input=session.messages, tools=available_tools,
        parallel_tool_calls=True,
    )
    await persist_and_dispatch_items(..., response.output, ...)
    session.messages.extend(response.output)
    sessions.record_usage(session, "main", response.usage, model=model, covered_items=len(session.messages))

    calls = [item for item in response.output if item.type == "function_call"]
    if calls:
        await tool_manager.execute_batch(...)  # 含批末系统提醒
    else:
        extra = trigger_hooks("Stop", session.messages)
        if extra is None:
            break
        await persist_and_append_system_message(extra)  # 代表现有落盘、分发、追加逻辑

    await compactor.maybe_compact(
        session,
        phase="mid_turn",
        instructions_provider=lambda: instructions,
        tools=available_tools,
        on_status=send_status,
    )
```

仅有托管工具输出时沿用现有结束判断。正常最终回答直接结束，哪怕它刚好跨过阈值，也留到下一轮轮前处理。每个检测点最多安装一次新历史，再按原流程前进。自动压缩开始与完成时通过 `on_status` 给入口发轻量 `status` 事件（如「正在自动压缩上下文…」/「上下文已自动压缩。」），避免等待摘要模型期间界面静默卡顿。普通请求若因本次超大用户输入或估算误差而被服务端拒绝，向入口报错；缩短输入并重试仅属于**摘要请求**内部逻辑。

### 2.3 手动命令与互斥

Terminal 和 QQ 已经共用斜杠命令识别，也都能展示 `status/error`。`/compact` 用入口携带的 `session_id` 查现有会话。空标识、`/new` 分配但尚未写入的标识、空历史均提示「当前会话还没有可压缩的历史」，不创建 JSONL。有中断调用时先按已有机制补齐结果，再生成摘要。

有一处并发问题需要随入口处理。现有 `try_acquire_session_lock()` 在同一 `owner_id` 下可再次成功，而一个摘要请求会 `await` 模型，其间另一条聊天可能写入同一会话。聊天和 `/compact` 在等待全局信号量**之前**共用占用检查：
- `math.isinf(session.expires_at)` 表示已有请求正在等待或执行，此时同来源也拒绝并提示「当前会话正在处理请求，请稍后再试」；
- 其他来源在有效保留期内拒绝并继续提示「该会话已被 … 占用，请稍后再试」；
- 已结束的保留期仍允许同来源立即进入；
- 审批答复保留现有优先通道；
- 取得占用后必须用 `try ... finally` 释放，失败或取消均能退出执行态。

这样可避免摘要返回时覆盖新消息，也无需第二把工具锁。

## 3. 模型声明、压缩配置与上下文估算

### 3.1 模型窗口声明与公共压缩配置

模型上下文窗口属于**模型静态元数据**，独立存放在新建包 `src/models/` 中集中维护，避免后续新增可选模型时每次都要改配置文件；压缩百分比和用户保留预算属于**所有模型共用的策略参数**，放在 `config.yaml` 中由 `Config.load()` 统一校验。

1. **模型注册表（`src/models/registry.py`）**：
   ```python
   @dataclass(frozen=True)
   class ModelInfo:
       """声明单个模型的上下文窗口等静态元信息。"""
       name: str
       context_window: int

   MODELS: dict[str, ModelInfo] = {
       "qwen3.7-flash": ModelInfo(name="qwen3.7-flash", context_window=1_000_000),
       # 后续按需直接在此补充其他可选模型
   }

   def get_model_info(model: str) -> ModelInfo:
       """按模型名查找静态元信息，未声明时显式报错。"""
       ...
   ```
   `AgentRuntime.__init__()` 启动时通过 `get_model_info(config.model)` 校验当前模型已在注册表中声明，缺失则立即报错提示补充。

2. **共用配置项（`config.yaml` / `src/config.py`）**：
   - `effective_window_percent: 95`（1~100 正整数）
   - `auto_compact_percent: 90`（1~100 正整数，且不大于 `effective_window_percent`）
   - `compact_keep_user_tokens: 20000`（正整数）

3. **衍生阈值（以 `W = 272000`、默认配置 `95 / 90 / 20000` 为例）**：

| 名称 | 算法 | 示例 | 用途 |
| --- | --- | ---: | --- |
| 原始上下文窗口 `W` | `model_info.context_window` | 272,000 | 两条百分比计算的共同基数，来自 `src/models/` |
| 有效上下文窗口 `H` | `W * effective_window_percent // 100` | 258,400 | 描述有效容量，供诊断和日志引用 |
| 自动触发阈值 `A` | `W * auto_compact_percent // 100` | 244,800 | 两处自动检测均使用 `estimated_context >= A` |
| 用户文本保留预算 `B` | `min(compact_keep_user_tokens, A // 2)` | 20,000 | 只分配给重建时的用户原文；大窗口直接取配置值，小窗口自动封顶防连续压缩 |

自动阈值直接按原始窗口计算，达到 `H` 时自然也已达到 `A`。摘要输入是否确实超出模型窗口，以服务端的上下文长度错误为准，避免因为粗估偏高而提前丢掉原文。

### 3.2 Session 保存什么

```python
@dataclass
class SessionUsage:
    """保存用于窗口判断的主请求计数，以及会话已记录的实际消耗。"""
    last_total_tokens: int | None = None  # 上次普通主响应的 usage.total_tokens
    covered_items: int = 0                # 该值已覆盖 messages[:covered_items]
    model: str | None = None              # 提供基准的模型，恢复时用于检查是否仍适用
    total_reported_tokens: int = 0        # 主请求与压缩响应的实际 total_tokens 之和

# 增加到现有 Session 的字段
usage: SessionUsage                       # 通过 default_factory 构造
summary_index: int | None = None          # 最近一次 compacted 的最后一个 item 在有效历史中的位置
```

正常主响应的 `usage.total_tokens` 已包含该次输入和模型输出。因此在 `response.output` **全部**追加后、任何工具结果追加前记录 `covered_items = len(session.messages)`。一次响应即使产生五个 output items，也只记一次 usage。输出内的 reasoning、工具请求和 assistant 文本均已由这个基准覆盖。

```python
def estimate_context(session, *, model, instructions_provider, tools):
    """以最近主响应校准估算，仅对尚未覆盖的历史项重新估算。"""
    u = session.usage
    if u.last_total_tokens is not None and u.model == model:
        return u.last_total_tokens + estimate_items(session.messages[u.covered_items:])
    return estimate_text(instructions_provider()) + estimate_schema(tools) + estimate_items(session.messages)
```

例如，主响应报告 `239000`，工具输出及批末提醒合计估算 `6100`，该轮续跑前即以 `245100` 触发压缩。主响应请求时的 instructions 和工具定义已包含在服务端计数中。同一轮复用它们；轮前判断衡量上一轮留下的上下文，本轮的新输入和新召回的记忆均未加入。无基准的轮前判断通过 `instructions_provider` 延迟构造基础系统提示词和当前工具定义进行估算。实际模型编码和隐藏推理可能带来偏差，以之后普通响应返回的 usage 重新校准。

- 安装新历史时清空 `last_total_tokens / covered_items / model`。摘要请求消耗的是旧历史，不能成为新窗口的计数基准。冷启动的旧 JSONL、换模型也走全量估算。
- 兼容接口偶尔省略 `usage` 时，保留仍有效的旧基准，继续估算尾部；无基准时按全量估算。累计只加服务端实际报告值。历史文件里从未保存过的用量无法事后算成真实值。
- 本阶段**不统计长期记忆召回与后台提取的用量**，保持 `src/memory/memory.py` 独立无耦合，仅记录主请求与压缩请求的消耗。缓存输入和推理明细已包含在服务端总数里，无需再加一遍。

### 3.3 单个 item 怎样估算

文本按 UTF-8 字节向上取整，`(len(text.encode('utf-8')) + 3) // 4`。图片按 `min(10000, ((width + 31) // 32) * ((height + 31) // 32))`，逐张相加。`1024 × 1024` 按 1,024 个 token 计；`4096 × 4096` 按上限 10,000 计。

估算器位于 `src/compact/estimator.py`，接受内存中的 SDK item 和恢复后的 dict，复用 `serializable()` 的序列化约定。对于文本、函数名和参数、reasoning 摘要、托管工具字段等，可用紧凑的 UTF-8 JSON 估算可见字段和少量结构开销。对 `message.content[]` 与 `function_call_output.output[]` 里的 `input_image` 单独处理，在用于估算的表示里去掉图片数据，另加尺寸对应的 token，只计算一次。工具结果使用模型实际收到的内容，而终端预览长度仅用于展示。

当前图片工具和 MCP 结果进入上下文时用的是 Data URL。使用 Pillow 从图片头读取宽高，避免为 JPEG、PNG、GIF、WebP 分别维护解析器，也无需解码像素。没有本地尺寸的远程 URL、文件引用或无法识别的头部按单图上限估算并记诊断日志，估算过程不联网。开发阶段只调整 `pyproject.toml`，依赖锁定和同步沿用项目约定。

## 4. 压缩管线

### 4.1 构造并发送摘要请求

在会话占用期间固定 `original = list(session.messages)`，另外创建 `working = [*original, compact_prompt_item]`。后续操作只改工作列表的成员顺序或删除成员，不改共享 item 的内容，因此无须深拷贝整段 Base64。`compact_prompt_item` 是仅供本次请求使用的中文 user 消息。旧摘要、图片、工具调用和结果都按普通历史传给摘要模型。

`COMPACT_PROMPT` 正文为：
> 请为继续当前任务的助手写一份简明交接摘要。保留用户目标和约束、已完成的工作、关键决定及原因、相关文件和标识、工具已确认的结果、失败或未验证事项、下一步。根据历史区分已完成与计划中的动作，仅输出中文摘要。

摘要请求使用现有 `AsyncOpenAI.responses.create(model=config.model, input=working)`，不提供可调用工具。读取成功完成的响应里的 `output_text`，忽略 reasoning 和其他非答案项。未完成或空白摘要作为失败处理。

### 4.2 超窗时如何裁剪

首次提交完整工作副本。遇到服务端明确的上下文长度错误后，删除副本中最旧的历史 item，再次提交；每次重试必须缩短副本。按错误码识别超窗，鉴权、限流、协议错误等按原错误上抛，额外裁剪不会修复这些错误。

若删除的是 `function_call` 或 `function_call_output`，同时移除副本内同 `call_id` 的另一端。并行调用有各自的 `call_id`，不能简单删除下一条。最近的真实历史全部删光后只会剩下摘要指令。把**最后一个有内容的历史单元加指令**作为最小有效请求；这个单元可以是一条消息，也可以是一对调用与结果。它仍超窗，即明确报错并保留会话原历史。这给「只剩一项」规定了可执行的边界，也避免用一条孤立的摘要指令生成空泛交接。

### 4.3 在原历史中选择保留项

1. 从 `original` 末尾向前遍历，候选限于真实 `role=user` 消息。`assistant`、`reasoning`、本地和托管工具请求、工具结果、Hook 系统提醒全部跳过。旧摘要参与上一步总结，在这一步按 `summary_index` 排除。该位置由检查点结构确定，用户自己粘贴了同样的前缀仍是有效用户输入。
2. 字符串内容按原文保留。内容块列表如果全是文本，预算允许时保留原有文本及块顺序；图文混合时只复制文本块，保留顺序；纯图片生成 `{"type": "message", "role": "user", "content": "[历史图片已省略]"}`（避免兼容端点拒绝空字符串 `user` 消息）。相邻文本块在计算文本预算或需要裁剪而合并时用换行隔开。保留预算在这里按提取的**文本**估算，原图、JSON 外壳和生成的摘要不扣这个预算。
3. 文本放得下就保留并扣减。第一条超出剩余预算时，拼成 `头部 + …中间已省略约 N 个 token… + 尾部`。`N` 按实际删除的中段 UTF-8 字节估算。先为标记留空间，再把可用字节约各半分给头尾，沿 Unicode 字符边界截取，复核包含标记的最终估算值。标记也放不下时结束选择，已有较新消息仍保留。
4. 遇到上述部分保留、预算耗尽或遍历完就停。反转选中列表，恢复旧到新的顺序，再追加一条摘要消息。中途为摘要请求删过哪些项，与这次选择相互独立。

固定 `SUMMARY_PREFIX = "【上下文压缩摘要】以下是此前对话的交接记录。请结合保留的用户原话继续任务，并以最新用户要求为准。"`，写入格式严格为 `SUMMARY_PREFIX + "\n" + summary_text`。检查点的最后一项总是这条摘要，因此无需给发往模型的消息增加私有来源字段。前缀的用途可对照 [Codex 摘要前缀原文](https://github.com/openai/codex/blob/e787cf7024fa66e4ec26c6c2ba9c122e045dedb9/codex-rs/prompts/templates/compact/summary_prefix.md)。

### 4.4 压缩器伪代码

`ContextCompactor` 放在 `src/compact/compactor.py`，由 `AgentRuntime` 创建全局唯一实例并注入到 `MessageProcessor` 与 `TurnRunner`。类自身无会话级可变状态，多会话并发调用互不干扰：

```python
class ContextCompactor:
    """全局共享单个实例，封装自动检测与手动压缩；工作副本仅在单次方法调用内存在。"""

    def __init__(self, client, config, sessions, model_info):
        """接收共享依赖和模型窗口元信息，派生有效窗口、自动阈值和保留预算上限。"""
        self.client = client
        self.config = config
        self.sessions = sessions
        self.model_info = model_info
        self.effective_window = model_info.context_window * config.effective_window_percent // 100
        self.limit = model_info.context_window * config.auto_compact_percent // 100
        self.keep_user_tokens = min(config.compact_keep_user_tokens, self.limit // 2)

    async def maybe_compact(self, session, *, phase, instructions_provider, tools, on_status=None):
        """供轮前和轮内调用，在非空历史达到阈值时安装一次摘要并通知状态。"""
        if not session.messages:
            return False
        estimated = estimate_context(
            session, model=self.config.model, instructions_provider=instructions_provider, tools=tools
        )
        if estimated < self.limit:
            return False
        if on_status is not None:
            await on_status("上下文接近窗口上限，正在自动压缩...")
        await self.compact(session, phase=phase)
        if on_status is not None:
            await on_status("上下文已自动压缩。")
        return True

    async def compact(self, session, *, phase):
        """从同一份原历史生成摘要和保留项，待磁盘提交成功后切换窗口。"""
        original = list(session.messages)
        working = [*original, {"type": "message", "role": "user", "content": COMPACT_PROMPT}]
        while True:
            try:
                response = await self.client.responses.create(model=self.config.model, input=working)
                break
            except APIStatusError as error:
                if not is_context_length_error(error) or not remove_oldest_unit(working):
                    raise

        summary_text = response.output_text.strip()
        if response.status != "completed" or not summary_text:
            self.sessions.record_usage(session, "compact", response.usage)
            raise ValueError("压缩模型未返回完整的文本摘要，已保留原上下文。")
        kept = retain_user_messages(original, session.summary_index, self.keep_user_tokens)
        summary = {"type": "message", "role": "user", "content": SUMMARY_PREFIX + "\n" + summary_text}
        self.sessions.install_compacted(session, [*kept, summary], response.usage)
```

`remove_oldest_unit()` 只在删除后仍有历史可供总结时返回 `True`；`phase` 只供日志标明 `manual / pre_turn / mid_turn`。`retain_user_messages()` 和首尾裁剪作为同模块纯函数。`install_compacted()` 前校验 `pending_calls` 为空。压缩器不执行工具、不分发摘要模型的原始输出，通道也不需要认识新的模型 item 类型。

## 5. JSONL 提交、恢复与用量记录

### 5.1 一次成功压缩写一条替换记录

现有 `messages` 行继续保存单个 Responses item。`compacted.payload` 直接是完整 `list[item]`，只含模型可见字段。存储元信息放到该行顶层的 `metadata`，写一行只增长一次 `ordinal`。下面三行是一段会话的连续片段：

```jsonl
{"timestamp":"2026-11-22T10:00:00+08:00","ordinal":41,"turn_id":6,"type":"token_usage","payload":{"source":"main","model":"qwen3.7-flash","total_tokens":244810,"covered_items":40}}
{"timestamp":"2026-11-22T10:00:02+08:00","ordinal":42,"turn_id":6,"type":"compacted","payload":[{"type":"message","role":"user","content":"保留已有注释。"},{"type":"message","role":"user","content":"【上下文压缩摘要】以下是此前对话的交接记录。请结合保留的用户原话继续任务，并以最新用户要求为准。\n已定位调用入口，下一步修改 TurnRunner。"}],"metadata":{"api_format":"openai_responses","summary_tokens":240000,"total_reported_tokens":920000}}
{"timestamp":"2026-11-22T10:00:08+08:00","ordinal":43,"turn_id":7,"type":"messages","payload":{"type":"message","role":"user","content":"继续实现。","metadata":{"api_format":"openai_responses"}}}
```

`SessionManager.install_compacted()` 先构造并校验新历史和累计计数，走 `storage` 共用的追加、`flush`、`fsync`。成功后在同一同步步骤内做 `session.messages[:] = replacement`、更新 `summary_index`、清空旧基准并应用累计值。切片赋值让已经持有列表引用的 `TurnRunner` 立刻看到新历史。磁盘已写完、内存尚未更新就退出时，重启仍能得到同样的新历史。发生半行写入时沿用现有完整行校验并报错，避免把损坏尾行当成成功提交。

### 5.2 为什么单列 `token_usage`

`response.usage` 属于整次请求，可能对应零个、一个或多个模型 output items。用轻量的 `token_usage` 记录持久化实际用量，避免把统计塞进某个回答正文或按 item 重复累加。它不进入 `session.messages`、UI 历史或模型输入。

- 普通主响应在全部输出落盘后写一条 `token_usage`（`source="main"`），保存模型、该次 `total_tokens` 和 `covered_items`。恢复时同时更新主基准和累计数。缺 `usage` 不编造记录。
- 成功摘要的消耗直接并入该条 `compacted` 的 `summary_tokens` 和截至提交时的 `total_reported_tokens`，不重复写统计行。摘要响应有用量但正文不可用时，只写一条 `source="compact"` 的 `token_usage` 计入累计并向上报错。
- 长期记忆的召回与后台提取不写 `token_usage`，避免跨模块耦合与后台任务插写 JSONL。

### 5.3 恢复算法

1. 从文件尾部按完整 JSONL 行向前查找顶层 `type == "compacted"` 的最近记录，按二进制块寻找换行、按完整行解码，记下字节偏移。无需把记录里的 Base64 或整个文件常驻内存。
2. 找到检查点，从其偏移正向读。校验其 `ordinal / turn_id` 为非负整数、格式标记、用户项列表和末项摘要。直接用列表初始化历史、`summary_index = len(payload) - 1`、`pending_calls = {}`、`usage.total_reported_tokens = metadata.total_reported_tokens`。下一条从 `checkpoint.ordinal + 1` 开始检查连续性，`turn_id` 可以延续或加一。
3. 接着应用后缀的 `messages` 和 `token_usage`。普通消息沿用现有 `api_format`、`call_id` 校验和未完成工具追踪。主响应的 `covered_items` 要与该统计记录出现时的有效历史长度相符。检查点之前的大段消息、工具对和旧基准无需重放。
4. 找不到检查点就从第 0 行按旧文件规则恢复，兼容全是 `messages` 的已有会话。文件末尾缺换行、有效后缀损坏或序号跳跃仍显式报错。轮次异常后的 `SessionManager.reload()` 走同一套恢复逻辑，同时恢复新增字段。

`list_sessions()` 继续从首条真实用户消息取预览，要先判断顶层 `type == "messages"` 再按 dict 读 `payload`。`history()` 继续返回有效上下文快照；压缩前的完整交互仍在原 JSONL。`TurnRunner` 给长期记忆召回和提取准备对话时，按 `summary_index` 跳过交接摘要，避免把模型归纳的文字作为用户原话。普通主请求和下一次摘要请求都能读到这条摘要。

## 7. 验收场景

| 场景 | 预期可观察结果 |
| --- | --- |
| 旧历史估算 `A - 1`，新输入使总量跨线；以及旧历史恰为 `A` | 前者正常开始新轮；后者先在旧 `turn_id` 发自动压缩状态并写一次检查点，再在新 `turn_id` 写入本次用户消息 |
| 一次响应并行调用两个工具，第二个结果使总量跨线 | 两个结果和批末提醒先落盘，然后写检查点并继续原 turn。模型调用和工具结果均未重复执行 |
| 最终回答跨线，或 `Stop` Hook 追加了续跑消息 | 最终回答后零次压缩；有续跑时追加系统消息后检查一次 |
| 空会话、低用量会话、正在执行的同来源会话分别收到 `/compact` | 分别得到空会话提示、一次压缩、当前会话正在处理请求提示。低用量会话成功后没有多出用户 turn |
| 超窗，旧工具对交错，或最小历史单元仍超窗 | 每次只缩短工作副本且调用结果成对；成功后仍从完整原历史选用户原文。最终失败时无 `compacted`，原历史仍能恢复 |
| 纯文本、图文、纯图、中文长文本、上次摘要，以及用户自己引用前缀 | 原文、仅文本、`[历史图片已省略]`、预算内首尾、排除旧摘要、保留真正的引用；重建列表最后只有一个 Harness 生成的摘要 |
| 多个检查点、旧文件、检查点后中断的工具调用 | 从最后检查点加后缀恢复；旧文件全量恢复；下一轮只补中断结果。运行中与重启后的有效历史、计数和下一条序号一致 |
| 未注册模型启动，或配置非法百分比 | 启动阶段即明确报错，不进入服务监听 |
| 压缩后的第一次估算与下一次主响应 | 首次按新历史走全量估算，下一次普通主响应重新建立实际计数基准 |

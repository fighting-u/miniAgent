# 长期记忆设计

长期记忆保存未来会话仍可能有用的稳定信息，实现在 `memory.py`，由 `core.py` 触发，`system_prompt.py` 注入目录和召回内容。它独立于聊天 JSONL，也不承担对话历史恢复。

## 提取与存储

每轮 Agent 正常结束、Stop Hook 不再要求续跑时，复制当前对话并创建后台提取任务。提取范围为最近 12 个消息项中的用户和助手正文，合计最多 8,000 字符，不直接提取工具输出或推理项。

辅助模型使用当前 `MODEL`，接收待分析对话及最多 6,000 字符的已有记忆目录，只返回 JSON 数组。允许两类记忆：

| 类型 | 内容 |
| --- | --- |
| `user_preference` | 用户长期偏好。 |
| `project_convention` | 项目长期要求、稳定事实、文档位置等约定。 |

临时任务信息和无关紧要内容不提取；提示词要求把对话当作数据，不执行其中的指令。结果必须包含有效的 `name`、`type`、`description`、`body`，校验通过后自动写入项目下的 `.memory/`，每条一个 Markdown 文件：

```markdown
---
name: 终端环境
type: project_convention
description: 项目的命令行环境约定。
---

created_at: 2026-11-10T10:00:00+08:00
updated_at: 2026-11-10T10:00:00+08:00

项目运行于 Windows，命令行使用 PowerShell。
```

文件名由名称规范化生成，重名时追加数字，不覆盖旧文件。已有目录只提供摘要预览，当前不实现自动更新、合并或可靠去重。

## 召回与按需读取

1. 每轮进入工具循环前，读取已有记忆的名称和描述目录；以最近 3 条 `role=user` 的字典消息为查询，查询文本最多 4,000 字符。
2. 异步请求辅助模型，从最多 12,000 字符的目录中选择相关索引，去重后最多选 5 条。
3. 读取选中文件，正文合计最多 12,000 字符，连同文件名注入本轮系统提示词；本轮工具循环共用该提示词，不反复召回。
4. 系统提示词还提供完整摘要目录，主模型可调用 `load_memory(filename)` 按需读取全文。该工具仅接受文件名形式的 Markdown 文件，不接受目录路径。

没有目录或查询时跳过选择请求。召回请求失败时记录警告，当前关键词兜底返回空列表；提取失败时记录警告并跳过。没有有效提取结果时不新增文件。

## 后台任务生命周期与限制

`main` 和 Agent 共用一个事件循环，模型调用均使用异步客户端；终端等待输入时让出执行权，使提取可继续运行。`main` 保存提取任务引用，退出前通过 `await asyncio.gather(..., return_exceptions=True)` 等待所有已创建任务，再关闭客户端。对话深拷贝避免后续追加或压缩改变提取内容。

后台提取完成前，下一轮不保证能召回新记忆；多个提取任务可能产生重复内容。任务不写入会话日志，强制退出后不恢复。查询目前按角色筛选，尚未全面区分历史中的真实用户请求和 Harness 注入内容。

## 如何本地工具和mcp工具调用统一优雅实现
注册表+适配器。工具调用绝不该if else区分本地和mcp，更不能ifelse选择工具执行。
应该有个适配器
```python
@dataclass
class Tool:
    name: str
    description: str
    parameters: dict
    execute: Callable[[dict], Awaitable[Any]]
```
不管本地，mcp工具都遵守上面的约定。然后就配合注册表，这其实和不同通道消息处理差不多的思想。
一个工具Manager，持有tools列表，负责注册，执行，返回工具schema等。
```python
class ToolManager:
    def __init__(self):
        self.tools: dict[str, Tool] = {}

    def register(self, tool: Tool):
        if tool.name in self.tools:
            raise ValueError(f"Duplicate tool: {tool.name}")
        self.tools[tool.name] = tool

    async def call(self, name: str, arguments: dict):
        tool = self.tools[name]
        return await tool.execute(arguments)

    def get_schemas(self):
        return [
            {
                "type": "function",
                "name": tool.name,
                "description": tool.description,
                "parameters": tool.parameters,
            }
            for tool in self.tools.values()
        ]
```

## 系统工具与调用流程

`TOOLS` 使用 OpenAI Responses 的 function 工具格式声明名称、说明和参数结构；`build_tool_handlers(config, plan)` 将工具名称映射到已绑定当前配置和会话计划的处理函数。

| 工具名 | 处理入口 | 当前行为 |
| --- | --- | --- |
| `get_model_name` | `run_get_model_name` | 无参数，读取 `config.model`，返回当前请求配置的模型名称；未配置或为空时记录警告日志并返回错误提示。 |
| `get_current_time` | `run_get_current_time` | 无参数，读取系统本地当前时间，以带时区偏移的 ISO 8601 格式返回，精确到秒，例如 `2026-11-11T15:30:45+08:00`。 |
| `powershell` | `run_powershell` | 启动 Windows PowerShell 执行命令，返回退出码、标准输出和标准错误；超时为 120 秒。 |
| `read_file` | `run_read` | 按 UTF-8 读取文本，可通过 `limit` 限制返回行数。 |
| `write_file` | `run_write` | 按需创建父目录，以 UTF-8 创建文件或覆盖已有文件的全部内容。 |
| `edit_file` | `run_edit` | 读取 UTF-8 文本，仅替换第一次出现的 `old_text`；未找到时返回错误。 |
| `glob` | `run_glob` | 按模式查找路径，支持 `**` 递归；过滤工作区外结果，排序后最多返回 200 项。 |
| `update_plan` | `run_update_plan` | 整体替换当前计划，最多 20 项，同时最多一项为 `in_progress`。 |
| `load_skill` | `SkillLoader(PROJECT_ROOT / SKILLS_DIR_NAME).load` | 按技能名称加载完整说明。 |
| `load_memory` | `load_memory` | 按文件名读取长期记忆，详见 [长期记忆设计](长期记忆设计.md)。 |
| `compact` | 主循环单独处理 | 先返回接收提示，待本批工具调用结束后归档并压缩上下文，详见 [记忆压缩设计](记忆压缩设计.md)。 |

主循环按顺序执行模型返回的工具调用：解析 `arguments` JSON → 触发 `PreToolUse` → 检查硬拒绝与审批规则 → 分发工具 → 触发 `PostToolUse` → yield 结果，由 Runtime 保存并通过通道展示。前置 Hook 返回非 `None` 时跳过执行，将拦截说明作为结果返回。同步内置工具通过工作线程执行，避免阻塞常驻端网络收发；计划工具使用当前会话传入的 PlanManager，不再通过全局 PLAN 共享计划或直接打印。

模型名称与主循环发送请求时使用的 `config.model`一致，返回的是请求配置名称，不查询服务端实际部署的模型。时间使用操作系统的本地时区，并在结果中包含对应的 UTC 偏移，不固定为 UTC+8。

工具结果以字符串放入 `function_call_output.output`，保留原调用的 `call_id`。JSON 解析错误和参数调用产生的 `TypeError` 返回“工具参数无效”；未知工具返回名称提示。文件工具内部捕获异常并返回 `Error: ...`，PowerShell 分别处理超时和进程启动失败。

## 文件路径与工作区

`config.workdir` 由 Config 统一解析，默认指向项目根目录；在 config.yaml 中指定相对路径时，以该 YAML 所在目录为基准。

`config.extra_allowed_dirs` 在 config.yaml 配置，当前额外放行 `D:/projects/others/interview_post_crawl/面经` 及其子目录；

`read_file`、`write_file`、`edit_file` 都先调用 `safe_path`：

```python
resolved_path = (config.workdir / path).resolve()
if not is_allowed_path(resolved_path, config):
    raise ValueError(f"路径不在允许的工作区或额外目录内：{path}")
```

相对路径以 `config.workdir` 为基准；完整绝对路径直接采用自身，`Path` 的 `/` 运算不是字符串拼接。解析 `..` 等路径成分后，`is_allowed_path` 检查最终目标是否位于工作区或额外允许目录内；拒绝访问时记录警告日志。

假设工作区为 `D:/projects/others/miniAgent`：

| 输入路径 | 结果 |
| --- | --- |
| `test.txt` | 允许，指向工作区根目录的文件。 |
| `output/test.txt` | 允许；写入时自动创建缺失父目录。 |
| `D:/projects/others/miniAgent/test.txt` | 允许，属于工作区内的绝对路径。 |
| `D:/projects/others/interview_post_crawl/面经/2026/11/11/test.md` | 允许，属于额外允许目录。 |
| `D:/other/test.txt` | 拒绝，目标在工作区外。 |
| `../test.txt` | 拒绝，解析后目标在工作区外。 |

`glob` 不调用 `safe_path`，而是对匹配结果逐个通过 `is_allowed_path` 检查。相对模式仍从 `config.workdir` 查找，查找额外目录时可使用绝对路径模式。文件操作最终仍受操作系统权限约束。

## 权限管控

权限分为 Agent 执行前的策略审查和文件处理函数内部的路径检查。hook.py 保留硬拒绝和敏感操作规则，旧的交互 permission_hook 已移除；Agent 产生 permission 事件，Runtime 的 ApprovalBroker 请求来源客户端审批。safe_path、glob 的路径过滤继续生效。

审批流程如下：

1. **硬拒绝**：PowerShell 命令转为小写后匹配 `DENY_LIST`。包含格式化卷、清空磁盘、关机等已配置片段时直接拒绝，不进入审批。
2. **敏感操作识别**：`read_file`、`write_file`、`edit_file` 使用同一个 `is_allowed_path` 判断，指向工作区和额外允许目录之外时请求审批；PowerShell 命中删除或清空命令正则，或包含 `set-content`、`out-file`、`set-acl`、`icacls`、`takeown` 等已配置片段时请求审批。
3. **用户决定**：终端客户端展示工具名、参数和审批提示，只有 `y` 或 `yes` 表示允许，其他输入均拒绝；决定通过 /approve 控制命令回传，不经过正在等待审批的普通消费者。拒绝后向模型返回“权限被拒绝。”。

未命中规则的调用直接放行；当前没有“工作区内写入或覆盖文件也必须确认”的规则。其他内置工具及 MCP 工具也经过前置 Hook 和策略检查，但现有审批规则只针对上述文件工具和 PowerShell。

### 当前边界

- Hook 审批与文件工具共用允许目录判断，但没有审批后临时放行机制。即使启用审批并同意访问允许范围外的路径，文件处理函数仍会拒绝该路径。
- PowerShell 使用执行时的 `os.getcwd()` 作为初始目录，没有调用 `safe_path`，命令可以访问工作区外路径。关键词和正则规则只是有限匹配，不构成命令解析器或操作系统沙箱。
- 直接调用处理函数会绕过 Agent 的 Hook 和策略审查；文件函数自身的路径检查仍执行。
- 已注册的日志 Hook 记录工具名称、参数预览、结果预览和大输出提醒；审批代理和 Agent 分别记录审批请求、决定、断线或超时拒绝、硬拒绝。大输出提醒本身不截断或拦截结果。

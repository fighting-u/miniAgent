# 工具设计

## 如何本地工具和mcp工具调用统一优雅实现
注册表+适配器。工具调用绝不该if else区分本地和mcp，更不能ifelse选择工具执行。
应该有个适配器
```python
@dataclass
class Tool:
    name: str
    description: str
    parameters: dict
    execute: Callable[[dict], Awaitable[Any]]
```
不管本地，mcp工具都遵守上面的约定。然后就配合注册表，这其实和不同通道消息处理差不多的思想。
一个工具Manager，持有tools列表，负责注册，执行，返回工具schema等。
```python
class ToolManager:
    def __init__(self):
        self.tools: dict[str, Tool] = {}

    def register(self, tool: Tool):
        if tool.name in self.tools:
            raise ValueError(f"Duplicate tool: {tool.name}")
        self.tools[tool.name] = tool

    async def call(self, name: str, arguments: dict):
        tool = self.tools[name]
        return await tool.execute(arguments)

    def get_schemas(self):
        return [
            {
                "type": "function",
                "name": tool.name,
                "description": tool.description,
                "parameters": tool.parameters,
            }
            for tool in self.tools.values()
        ]
```

## 统一工具结果以支持图片及列表结果

统一工具结果dataclass
```python
@dataclass
class TextContent:
    """供模型读取的一段原始文本。"""
    text: str


@dataclass
class ImageContent:
    """一张图片，保留实际 MIME 类型和完整的纯 Base64。"""
    mime_type: str
    data: str


@dataclass
class ToolResult:
    """保存一次工具执行产生的有序内容及错误标记。"""
    content: list[TextContent | ImageContent]
    is_error: bool = False

    def log_output(self) -> str:
        """生成供终端与日志共用的单行预览。"""
        ..
```
然后本地工具都遵守返回值为ToolResult规范，mcp规范返回的都转为ToolResult规范。再用`common.py` 中的 `to_openai_tool_output()`将ToolResult转为OpenAI Responses 的工具结果规范就行。
日志的话，图片不展示base64编码，直接ToolResult里定义个log_output方法，输出格式就如“执行成功，返回 x 张图片，文本预览”，不超过50字符。

# 多模态工具结果改造方案

**待验收。** 本地工具和 MCP 工具统一返回 `ToolResult(content, is_error)`。在 `ToolManager.execute_batch()` 取得结果后，用一个函数把它转换为 OpenAI Responses 的 `function_call_output`。下一次模型请求和会话 JSONL 共用这份 API 数据。运行日志与终端共用 `ToolResult.log_output()` 的短摘要。

## 1. 从工具到模型

| 环节 | 改动 |
| --- | --- |
| 本地工具 | 每个已注册的处理函数显式返回 `ToolResult`。工具自己最清楚哪些分支是失败 |
| MCP 入口 | `MCPManager._call_tool()` 调用 `from_mcp_result()`。删除当前将整份 MCP 回复转成 JSON 字符串的逻辑 |
| 单次执行 | `ToolManager.execute()` 返回 `ToolResult`，删除 `str(await tool.execute(...))`。审批、会话读写锁和工具注册方式沿用现有流程 |
| 批量提交 | `execute_batch()` 给每个结果配上原调用的 `call_id`，调用 `to_openai_tool_output()`。按模型调用顺序提交，完成后触发一次 `PostToolBatch` |
| 会话与展示 | JSONL 保存 API 结果及 `metadata`。模型拿完整内容。日志、终端实时事件和恢复历史使用同一格式的摘要 |

`ToolResult` 的生命周期到**本次执行结果完成转换**为止。新增图片工具只需构造图片块。将来为另一家模型转换工具输出时，替换结果转换函数即可。工具声明、模型调用输入、托管工具等其他厂商差异，留到接入该厂商时处理。

## 2. 数据契约与日志摘要

建议把以下类型放在已有的 `src/tools/tool.py`，和 `Tool`、`ToolContext` 放在一起。运行期按 dataclass 类型区分内容块，MCP 和 OpenAI 各自的 `type` 字符串由转换函数处理。

```python
@dataclass
class TextContent:
    """供模型读取的一段原始文本。"""
    text: str


@dataclass
class ImageContent:
    """一张图片，保留实际 MIME 类型和完整的纯 Base64。"""
    mime_type: str
    data: str


@dataclass
class ToolResult:
    """保存一次工具执行产生的有序内容及错误标记。"""
    content: list[TextContent | ImageContent]
    is_error: bool = False

    def log_output(self) -> str:
        """生成供终端与日志共用的单行预览。"""
        ...


def text_result(text: str, *, is_error: bool = False) -> ToolResult:
    """将现有文本工具的成功输出或错误原因包装为工具结果。"""
    return ToolResult([TextContent(text)], is_error=is_error)
```

**成功。** 允许纯文本、纯图片、图文交错和空结果。块顺序就是模型接收顺序。图片使用实际的 MIME 类型，`data` 保存原始编码，不带 Data URL 前缀。例如 `ToolResult([TextContent("原图"), ImageContent("image/png", data)])`。

**失败。** `is_error=True` 时，工具只放一个包含具体原因的 `TextContent`，例如 `text_result("文件不存在", is_error=True)`。转换器取第一个文本块，统一拼成字符串 `工具执行失败，错误信息：文件不存在`。前缀由转换器加一次。文件正文即使以“错误”开头，只要读取成功，仍是成功结果。

**日志与终端。** `log_output()` 返回字符串，由调用方决定写日志或显示。成功摘要从“执行成功”开始，有图片时追加“返回 X 张图片”，有文本时再追加文本。多块文本按原顺序取预览，以空格连接并把换行折成空格，所有文本合计最多 50 个字符，超出时加省略号。图片只计数，不访问编码正文。失败摘要使用相同的文本预览预算，模型收到的错误原因仍是全文。

| 工具返回 | `log_output()` 示例 |
| --- | --- |
| 一段文本 | `执行成功，计划更新成功` |
| 两张图片和文字 | `执行成功，返回 2 张图片，已读取两张图表` |
| 只有一张图片 | `执行成功，返回 1 张图片` |
| 成功且无内容 | `执行成功` |
| 错误文本 | `工具执行失败，错误信息：文件不存在` |

## 3. 本地工具、执行器与 Hook

- **注册契约。** `Tool.execute` 的签名收紧为 `Callable[[dict[str, Any], ToolContext], Awaitable[ToolResult]]`。`register_local_tool()` 接受返回该类型的同步或异步函数。保留参数白名单、上下文注入，以及同步线程在取消时先结束再释放锁的行为。
- **文本工具。** `run_read/run_write/run_edit/run_glob` 在各自已有分支用 `text_result()` 包装结果。零匹配是成功，目录无效、读写失败、未找到待替换文本是错误。`run_get_current_time/run_get_model_name` 包装其正常文本即可。
- **PowerShell。** `run_powershell()` 成功时保留当前供模型读取的退出码和标准输出、标准错误文本。非零退出时返回一个错误文本块，写明退出码和命令给出的诊断。超时或无法启动时返回对应原因。是否失败取决于退出状态，单有 stderr 不代表失败。
- **计划、技能与记忆。** `run_update_plan()` 包装计划更新成功或校验失败的结果。`run_load_skill()` 和已注册的 `load_memory()` 在查找失败处分支置错。若 `SkillLoader.load()` 当前把缺失编码进普通字符串，应让它向入口显式报告缺失。保留 `Plan`、技能目录和记忆读取函数供其他调用方使用的普通接口。
- **调度与错误。** `execute()` 将无效参数、审计拒绝、审批未通过和未注册工具转为各自的失败结果。安全审计继续返回 `str | None`。`execute_batch()` 把单个任务的普通异常转成该次调用的失败结果，继续提交同批其他结果。取消及写盘失败走现有中断恢复路径。
- **记录时机。** `PostToolUse(call, result)` 仍表示实际工具执行返回。建议将当前 `tool_output_log_hook()` 的结果日志移到 `execute_batch()` 得到最终结果后，那里成功、拒绝及异常都有对应的结果。调用一次 `result.log_output()`，用同一个字符串写日志、传终端和保存摘要，避免两处重复打印。`large_output_hook()` 改为分别统计文本和图片编码长度，沿用已有大输出提醒。`summary_hook()` 继续按 `function_call_output` 计数。

## 4. MCP 结果读取规则

在 `src/tools/mcp_manager.py` 增加 `from_mcp_result(result: CallToolResult) -> ToolResult`。stdio 和 HTTP 共用它。MCP 的 `content` 是有类型、有顺序的块列表，`structuredContent` 是由工具定义形状的 JSON 对象。[MCP 工具结果规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

1. **先选数据来源。** `content` 只要非空就选它，按返回顺序解析。哪怕它只含未知块，或只有一个内容为空字符串的文本块，也不再读取 `structuredContent`。两处同时返回同一张图时，这条规则可以避免重复发送图片。
2. **标准块逐个转换。** SDK 的 `TextContent.text` 进入本地文本块。`ImageContent.mimeType/data` 进入本地图片块，保留纯 Base64。音频、资源链接、嵌入资源等其他类型在原位置生成短文本，如“暂不支持 MCP 内容类型 audio”。该说明只含类型，原块不整体序列化到文本里。一个不支持的块不会覆盖旁边可用的图文。
3. **仅在 `content=[]` 时手动解析 `structuredContent`。** 建议首版支持直接给出的单块字典，及项目中使用的 `{"result": [...]}` 包装。按显式 `type` 取字段，`{"type":"text","text":"图表"}` 转文本，`{"type":"image","mimeType":"image/png","data":"..."}` 转图片。其他块或无法识别的对象在对应位置标注“暂不支持”，不递归扫描任意字段猜测图片，也不将整个 JSON 打印给模型。两个来源都没有内容时，成功结果为 `ToolResult([])`。
4. **统一失败契约。** MCP 的 `isError=True` 表示工具报告失败。按同样的来源优先级取得第一条实际错误文本，只保留这个文本块。如果远端没有给出文字原因，使用“远端工具报告失败，未提供错误说明”。协议异常、连接中断或超时由 `_call_tool()` 返回相应的失败文本。成功回复里出现不支持的类型只说明呈现能力有限，不改写远端成功状态。

## 5. 一个函数转换成 OpenAI 工具输出

建议将 `to_openai_tool_output(call_id: str, result: ToolResult) -> dict` 放在新模块 `src/tools/openai_output.py`，作为批量执行和中断恢复共用的纯函数。它只构建 API 数据，无需访问注册表、会话或模型客户端。

| 输入 | `function_call_output.output` |
| --- | --- |
| `is_error=True` | 取第一个 `TextContent.text`，返回完整字符串 `工具执行失败，错误信息：{原因}` |
| 成功，空列表或单文本块 | 分别返回空字符串或原始文本字符串，兼容现有纯文本工具 |
| 成功，多块或包含图片 | 返回有序数组。文本映射为 `input_text`，图片映射为 `input_image`，在这里拼接一次 Data URL |

例如同一个调用返回说明和一张 PNG。下面的 `<PNG_BASE64>` 在实际请求及 JSONL 中都是完整编码。[OpenAI 函数调用指南](https://developers.openai.com/api/docs/guides/function-calling)

```json
{
  "type": "function_call_output",
  "call_id": "call_chart",
  "output": [
    {"type": "input_text", "text": "第 2 页的折线图"},
    {"type": "input_image", "image_url": "data:image/png;base64,<PNG_BASE64>"}
  ]
}
```

## 6. JSONL、模型回放与终端历史

**JSONL 延续 API 原格式。** 外层保留 `timestamp/ordinal/type/turn_id/payload`。同一例子的 `payload` 如下。建议除已确认的 `is_error` 外，也把 `log_output()` 生成的短字符串保存为 `metadata.log_output`，使重启后终端可直接显示当时的摘要。

```json
{
  "type": "function_call_output",
  "call_id": "call_chart",
  "output": [
    {"type": "input_text", "text": "第 2 页的折线图"},
    {"type": "input_image", "image_url": "data:image/png;base64,<PNG_BASE64>"}
  ],
  "metadata": {
    "api_format": "openai_responses",
    "is_error": false,
    "log_output": "执行成功，返回 1 张图片，第 2 页的折线图"
  }
}
```

- **写入和请求。** `execute_batch()` 组装一个工具结果条目，由 `persist_and_dispatch_items()` 提交。`storage.append()` 在已有 `metadata.api_format` 旁合入工具结果的两个附加字段，保留 `False`。建议在 `session.messages` 的工具结果字典上也保留这两个字段，供实时和历史展示取用。在 `TurnRunner.run_turn()` 构造主请求的 `input` 时，仅从带本地元信息的工具结果浅拷贝中移除 `metadata`。同一份 API `output` 可直接复用，完整图片仅在结果中保存一次。
- **读回和展示。** `storage.load()` 继续校验 `api_format`、序号和调用配对，对新工具结果还原上述两个展示字段。实时分发和 `SessionManager.history()` 共用通道条目转换，取摘要后再构造发给客户端的事件。`TerminalUI.show_items()` 直接打印摘要。旧 JSONL 没有摘要时截取原有文本预览，若旧 `output` 为数组则按块预览图片数量和文本，状态未知时只显示“工具结果”。旧记录按原始 API 内容回放，历史里的 JSON 字符串继续当文本。
- **配对和恢复。** 原调用仍先随模型响应落盘。`_validate_call()/_track_call()` 继续只按原 `function_call`、`function_call_output` 和 `call_id` 配对。`recover_pending_tools()` 为缺结果的调用用现有“执行效果未知”说明生成失败结果、摘要和元信息，复用同一个 OpenAI 转换函数。存储层直接从 `openai_output.py` 导入该函数，避免反向依赖 `ToolManager`。
- **范围。** 图片 Base64 随 API 数据正常落盘。上下文压缩、图片转存、跨厂商会话回放均留待后续。QQ 继续只发送助手回答。

## 7. 实施顺序与验收

1. 在 `tool.py` 定义结果类型、`text_result()` 和 `log_output()`，迁移十个本地入口及 MCP 调用，收紧注册器和单次执行返回类型。
2. 加入共享 OpenAI 转换函数，接通批执行、失败结果和中断恢复。保留工具锁、原调用顺序、托管搜索分支和批末提醒。
3. 接入存储元信息、模型请求过滤、日志及通道摘要。用同一条结果核对 JSONL、模型输入、日志和终端四处的数据边界。
4. 验收纯文本、纯图片、交错图文、空结果、超过 50 字的文本、并行调用和历史恢复。特别检查 MCP 两个来源同时有数据时只取 `content`，以及 `content=[]` 时能从 `structuredContent.result` 恢复图文。
5. 错误结果只带一个错误文本，API 的 `output` 是带统一前缀的完整字符串，磁盘上 `metadata.is_error=true`，日志和终端仅显示短预览。旧会话无新字段仍能打开。配置的 Qwen 兼容端点能否实际读到工具结果中的图片，需要在实施后用一张文字提示中没有描述答案的图片单独验证。

# 记忆压缩设计

本文记录当前对话上下文的压缩机制，实现在 `context_compactor.py`，由 `core.py` 调用。目标是在保留任务续接信息的同时减少发送给模型的历史内容；跨会话的稳定信息另见 [长期记忆设计](长期记忆设计.md)。

## 触发方式

- 请求前：每次主模型请求前调用 `prepare`，先控制工具结果大小、裁剪历史，再按上下文大小决定是否继续压缩。
- 模型主动：模型调用 `compact` 后，先保存本批工具调用与结果，再归档并生成摘要。
- 请求超限：识别上下文超限错误后执行响应式压缩，同一次模型请求最多补救重试一次。

大小按消息序列化后的字符数估算，不精确计算 Token，也不包含系统提示词和工具定义。当前上下文阈值为 560,000 字符，第三、四步以其 80% 为目标。

## 请求前的五步管线

| 步骤 | 条件与处理 |
| --- | --- |
| 1. 工具结果预算 | 最近一次模型输出后的未读工具结果合计超过 200,000 字符时，从大到小处理单条超过 30,000 字符的结果：全文落盘，原位置保留路径和 2,000 字符预览。 |
| 2. 历史裁剪 | 超过 50 条逻辑消息时，归档裁剪前的全部上下文，保留开头 3 条、归档标记和最近 46 条；根据调用配对调整边界，实际保留数可能增加。 |
| 3. 旧结果缩减 | 上下文仍超阈值时，把已读工具结果中最近 3 条以外的较长结果替换为文件路径，直到达到目标或没有可处理项。 |
| 4. 最近结果缩减 | 仍超阈值时，从大到小缩短未读结果及最近 3 条已读结果，保存全文并保留路径和 1,000 字符预览。 |
| 5. 模型摘要 | 仍超阈值时，归档全部上下文，异步请求模型生成事实摘要，再以包含当前请求、摘要和归档路径的一条消息替换历史。 |

逻辑消息按连续的模型输出、连续的工具结果分别合并计数，其他消息各算一条，不是直接统计 API item 数量。裁剪边界避免拆开模型输出及 `call_id` 配对；无法安全裁剪时跳过第二步。

主动压缩直接执行第五步。响应式压缩则总结旧历史，并尽量完整保留最近 5 个消息项；同样调整边界以保留调用配对。

## 归档与续接

- 工具全文写入 `.task_outputs/tool-results/<call_id>.txt`；当前上下文写入 `.transcripts/transcript_<uuid>.jsonl`，每行一个消息项。
- 摘要保留目标、用户约束、重要决定、涉及文件、已完成工作和剩余工作。摘要输入最多取历史序列化文本的 80,000 字符，超出时保留前 25% 和后 75%。
- 历史裁剪标记和摘要消息当前使用 `role=user`；工具结果缩减保留原有 `call_id`。
- 模型需要细节时，通过现有文件工具检索或分段读取归档，不自动把完整归档重新塞回上下文。

## 当前限制

压缩会改变运行中的 `messages`，但尚未把压缩替换状态写成会话日志中的 `compact` 记录。重新加载会话不能完整重建压缩后的上下文；恢复约定见 [持久化设计](持久化设计.md)。字符预算是近似值，摘要也可能遗漏细节，归档保留的是当时可见的上下文。
